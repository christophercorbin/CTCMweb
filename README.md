# CargoLink Barbados

A freight forwarding management system for Caribbean Trade & Cargo Management (CTCM). Allows customers to register, track shipments, and manage invoices — with a full admin back-office for managing customers, shipments, packages, charges, and warehouse receipts.

## Quick Start

```bash
# Install dependencies
npm install

# Start Amplify sandbox (deploys real AWS resources, generates amplify_outputs.json)
npx ampx sandbox

# Start frontend dev server (separate terminal)
cd apps/web && npm run dev
```

Frontend runs at `http://localhost:5173`. Requires `amplify_outputs.json` generated by the sandbox.

## Tech Stack

- **Frontend**: React 18 + TypeScript + Vite + Tailwind CSS
- **Backend**: AWS Amplify Gen 2 (AppSync GraphQL + DynamoDB)
- **Auth**: Amazon Cognito (email/password, `admin` + `customer` groups)
- **Storage**: Amazon S3
- **Email**: Amazon SES
- **OCR**: Amazon Textract (via Step Functions)
- **Hosting**: AWS Amplify (CI/CD on push to `main`)

## Features

### Customer
- Self-registration with email verification
- Real-time shipment tracking dashboard
- Ship / Hold instructions per shipment
- Pending packages view
- Invoice history
- Skybox addresses (Miami air + sea warehouse)

### Admin
- Customer management (create with Cognito account + SES welcome email)
- Full shipment lifecycle management (create, edit, delete)
- Package, charge, and event management per shipment
- Status updates with automated SES notification emails
- Invoice management
- Warehouse receipt intake with Textract OCR

## Development

### Prerequisites

- Node.js >= 20
- npm >= 9
- AWS CLI configured with appropriate credentials

### Commands

```bash
# Backend
npx ampx sandbox              # Deploy sandbox + watch for changes
npx ampx generate outputs     # Regenerate amplify_outputs.json

# Frontend
cd apps/web && npm run dev    # Dev server
cd apps/web && npm run build  # TypeScript check + Vite build
cd apps/web && npm run lint   # ESLint
```

### Configuration

No `.env` files needed. The frontend reads all config from `amplify_outputs.json`, which is auto-generated by `npx ampx sandbox` or the Amplify CI/CD pipeline. Never commit `amplify_outputs.json` to version control.

Backend environment variables (Lambda env vars, IAM policies) are all managed in `amplify/backend.ts` via CDK.

## Deployment

Every push to `main` triggers Amplify's CI/CD pipeline, which builds the frontend and deploys backend changes. The `develop` branch is for active development; PRs target `main`.

- **Develop**: `https://develop.d1yo6c4008x99n.amplifyapp.com`

## Authentication

- Login with email + password (`USER_PASSWORD_AUTH` flow, explicitly enabled on Cognito App Client)
- Self-registered customers are auto-assigned to the `customer` group via post-confirmation Lambda
- Admin accounts are provisioned manually in the Cognito console and added to the `admin` group
- Admin-created customer accounts go through a `FORCE_CHANGE_PASSWORD` flow on first login
- The login page handles the new-password challenge transparently
