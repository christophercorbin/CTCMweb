## 1. Project Overview

**CargoLink Barbados** is a freight forwarding management system for CTCM (Caribbean Trade & Cargo Management). It allows:

- **Customers** to register, track shipments, view invoices, and give ship/hold instructions
- **Admins** to manage customers, shipments, packages, charges, invoices, and process warehouse receipts via OCR

### Data Flow

```
Frontend (React)
  ↓ aws-amplify client (AppSync)
AppSync (GraphQL API, IAM + Cognito auth)
  ↓
DynamoDB (via AppSync auto-resolvers)
  ↓ custom mutations → Lambda functions
Lambda (status-notifier, adminCreateCustomer, etc.)
  ↓
SES (email), Cognito (user management)
```

### Auth Flow

1. **Self-registration**: Customer signs up at `/register` → email verification at `/confirm` → post-confirmation Lambda creates DynamoDB Customer record + adds to `customer` group + sets `custom:customerId` and `custom:role`
2. **Admin-created accounts**: Admin uses CustomerManagement component → `createCustomerWithAccount` mutation → `adminCreateCustomer` Lambda → `AdminCreateUser` (FORCE_CHANGE_PASSWORD) + SES welcome email → customer logs in at `/login` → `CONFIRM_SIGN_IN_WITH_NEW_PASSWORD_REQUIRED` challenge handled with new-password step
3. **Login**: `USER_PASSWORD_AUTH` flow (explicitly enabled via CDK — required since Amplify Gen 2 defaults to SRP only)

## 5. Environment Variables

All backend env vars are injected via `amplify/backend.ts` CDK code — NOT `.env` files.

| Lambda | Env Var | Set By |
|---|---|---|
| `adminCreateCustomer` | `USER_POOL_ID` | `backend.ts` CDK |
| `adminCreateCustomer` | `GRAPHQL_API_ENDPOINT` | `backend.ts` CDK |
| `postConfirmation` | `GRAPHQL_API_ENDPOINT` | `backend.ts` CDK |
| `ocrTrigger` | `STATE_MACHINE_ARN` | `backend.ts` CDK |

**Important**: Amplify auto-injects `AMPLIFY_DATA_GRAPHQL_ENDPOINT` for `allow.resource()` functions, but our Lambdas use `GRAPHQL_API_ENDPOINT`. These are **manually set** in `backend.ts` with `addEnvironment("GRAPHQL_API_ENDPOINT", (backend.data.resources.graphqlApi as any).graphqlUrl)`.

Frontend config comes entirely from `amplify_outputs.json` (generated by sandbox/deploy), loaded in `apps/web/src/lib/amplify.ts`.

## 7. Coding Conventions

### Frontend

- **TypeScript** everywhere — no `any` except where Amplify types are missing (e.g., `.graphqlUrl` cast)
- **Tailwind CSS** for all styling — no CSS files, no CSS-in-JS
- **lucide-react** for icons
- **react-hot-toast** for all user feedback (success/error toasts)
- **react-hook-form + Zod** for all forms
- **Component pattern**: Named exports (not default) for components, default export for `App`
- **Auth helpers**: All Cognito calls go through `apps/web/src/lib/cognito.ts` — never call `aws-amplify/auth` directly from components
- **GraphQL client**: Use `apps/web/src/lib/graphql.ts` or the Amplify-generated client from `amplify_outputs.json`
- **Error handling**: Always destructure `err as { name?: string; message?: string }` and handle specific Cognito error names

### Amplify / Backend

- **Lambda runtime**: Node 20 (`runtime: 20`), TypeScript compiled
- **AppSync auth**: Models use `allow.owner()` + `allow.group("admin")` pattern
- **Custom mutations** requiring Lambda: defined in `amplify/data/resource.ts` with `.handler(a.handler.function(...))`
- **IAM permissions**: Granted in `amplify/backend.ts` via `addToRolePolicy` — never baked into Lambda code
- **`resourceGroupName: "data"`**: Used on Lambdas that are custom mutation handlers to avoid CDK circular dependency issues
- **No `as any` except**: `(backend.data.resources.graphqlApi as any).graphqlUrl` — Amplify type gap

### Git

- Branch: `develop` (active development)
- PRs target: `main`
- Commit style: `type: description` (feat, fix, refactor, docs, chore)

## 8. Current State (as of March 2026)

### Working Features

**Customer-facing:**
- Self-registration (`/register` → `/confirm` → `/login`)
- Dashboard with real-time shipment list (`observeQuery`)
- Shipment details view
- Ship/Hold instruction (`customerInstruction` field on Shipment)
- Pending packages view (`/dashboard/pending-packages`)
- Customer info page (`/customer-info`)
- Invoices (`/invoices`)

**Admin-facing:**
- Admin dashboard with all customers and shipments
- Create customer (with Cognito account + SES welcome email)
- Shipment management: create, edit, delete
- Package management: add, edit, delete per shipment
- Shipment charges: add, edit, delete
- Shipment events (timeline)
- Status updates with automated SES email notifications
- Admin invoices (`/admin/invoices`)
- Warehouse receipt intake (`/admin/warehouse-receipt`) — OCR via Textract
- Email broadcast (`/admin/broadcast`) — branded announcement emails to all/selected customers with live preview, test send, async background sending, and broadcast history (`Broadcast` model)

**Auth:**
- `USER_PASSWORD_AUTH` explicitly enabled on Cognito App Client
- New-password challenge handled in Login for admin-created (FORCE_CHANGE_PASSWORD) accounts
- `UserNotConfirmedException` → redirects to `/confirm?email=...`
- Forgot password flow (`/forgot-password`) — request code + confirm new password, linked from Login

**Email (SES):**
- Status notification emails via `statusNotifier` Lambda
- Welcome email on admin-created accounts via `adminCreateCustomer` Lambda
- Broadcast emails via `broadcastEmail` Lambda (async self-invoke fan-out, SES rate-limited batches of 10/sec)
- Unsubscribe: HMAC-tokenized link in broadcasts → public `unsubscribe` Lambda function URL → sets `Customer.emailOptOut` (reason UNSUBSCRIBED). Shared secret: `UNSUBSCRIBE_SECRET` env var (set in Amplify Console for prod; insecure dev fallback in code)
- Bounce/complaint handling: SES identity notifications (wired via CDK custom resource) → SNS topic → `sesEvents` Lambda → flags `Customer.emailOptOut` (reason BOUNCED/COMPLAINT). Broadcasts skip opted-out customers; transactional email unaffected

**Monitoring:**
- CloudWatch error alarms on every Lambda + OCR Step Functions failures → SNS `AlertsTopic` (dedicated `alerting` stack, no cross-stack cycles) → email to `ALERT_EMAIL` env var (default christopher@cargolinkbarbados.com). Subscription must be confirmed once via the AWS email. Alarms also send recovery (OK) notices.

### Known Gaps / Not Yet Built

- Customer-side document uploads (receipts, invoices)
- Full OCR result persistence UI
- Delivery confirmation workflow
- Customer invoice payments

## 9. Important Context

### Cognito User Pool

- **Pool ID**: `us-east-1_YfQ4BVEry`
- **Region**: `us-east-1`
- **Groups**: `admin`, `customer`
- **Custom attributes**: `custom:customerId` (DynamoDB PK), `custom:role`
- **Auth flows enabled**: `USER_SRP_AUTH`, `USER_PASSWORD_AUTH`, `REFRESH_TOKEN_AUTH`
- **MFA**: OFF
- **Admin users**: Provisioned manually via Cognito console and added to `admin` group

### DynamoDB / AppSync Models

| Model | Key Fields | Authorization |
|---|---|---|
| `Customer` | `id`, `name`, `email`, `cognitoSub`, `airSkyboxAddress`, `seaSkyboxAddress` | owner + cognitoSub + email + admin |
| `Shipment` | `trackingNumber`, `status`, `type`, `customerId`, `customerCognitoSub`, `customerInstruction` | owner via `customerCognitoSub` + admin |
| `Package` | `shipmentId`, `trackingNumber`, `weight`, `dimensions`, `type` | owner via Shipment + admin |
| `ShipmentCharge` | `shipmentId`, `chargeType`, `amount`, `description` | admin only |
| `ShipmentEvent` | `shipmentId`, `status`, `description`, `location` | admin write, customer read |
| `Invoice` | `customerId`, `shipmentId`, `status`, `amount`, `dueDate` | owner + admin |

### S3 Storage Prefixes

| Prefix | Purpose |
|---|---|
| `receipts/` | Customer-uploaded purchase receipts (triggers OCR) |
| `invoices/` | Generated/uploaded invoices |
| `documents/` | General documents |
| `shipments/` | Shipment-related files |

### Skybox Addresses

Each customer has `airSkyboxAddress` and `seaSkyboxAddress` — Miami warehouse addresses used as shipping destinations from US retailers. These are displayed to customers and included in welcome emails.

### Demo Mode

The Login page has "Preview UI (No Backend Required)" buttons. These call `enableDemoMode()` / `enableAdminDemoMode()` from `apps/web/src/utils/mockData.ts`, which populate mock data for UI previewing without a backend connection.

### Legacy Type Names

`apps/web/src/types/index.ts` contains frontend types with snake_case fields (e.g., `tracking_number`, `customer_id`) — a legacy artifact from the original Supabase implementation. The actual DynamoDB/AppSync models use **camelCase** (`trackingNumber`, `customerId`). There may be mapping logic in hooks/pages.
